### Шортлист моделей и процедура окончательного выбора  

#### Флагман – классификатор подозрительных операций  

| Кандидат | Почему в шортлист | Требуемые ресурсы | Пороговые метрики (приёмочные) |
|----------|-------------------|-------------------|--------------------------------|
| **LightGBM** | Проверенный в банковских задачах, быстрая inference, легко интерпретируемый SHAP‑анализ | CPU 2 vCPU, 8 GB RAM | Recall ≥ 0.85 при FPR ≤ 0.05; latency ≤ 50 ms |
| **CatBoost** | Хорошо работает с категориальными признаками, автоматическая работа с missing | CPU 2 vCPU, 8 GB RAM | Same as above |
| **TabPFN (PyTorch)** | Быстрый предтренинг, потенциальный прирост Recall | GPU 1 × Tesla T4 | Recall ≥ 0.88; latency ≤ 40 ms (GPU) |

**Процедура выбора**  

1. Обучить каждый кандидат на контрольной выборке (10 k операций).  
2. 5‑fold валидация → собрать Recall, Precision, ROC‑AUC, latency.  
3. Запустить **business‑critical тест**: 1 000 новых операций в прод‑стриме, измерить количество истинных срабатываний (по последующей проверке).  
4. Выбрать модель, удовлетворяющую **Recall ≥ 0.85** при **FPR ≤ 0.05** и **latency ≤ 50 ms**.  
5. Если ни одна модель не достигает порога → увеличить контрольную выборку до 30 k и повторить.

#### OCR документов к кредитной заявке  

| Кандидат | Почему в шортлист | Требуемые ресурсы | Приёмочные метрики |
|----------|-------------------|-------------------|--------------------|
| **LayoutLMv3 (Transformer)** | Лучшее качество на полях с таблицами, поддержка русского языка | GPU 1 × Tesla T4, 16 GB VRAM | F1 ≥ 0.95 на ключевых полях (ИНН, суммы); latency ≤ 200 ms |
| **Tesseract + правила пост‑обработки** | Дешёвый, быстрый, легко поддерживается | CPU 4 vCPU, 16 GB RAM | F1 ≥ 0.95; latency ≤ 120 ms |
| **Azure Form Recognizer (cloud)** | Высокое качество, но нарушает on‑prem | – | – (исключён) |

**Процедура выбора**  

1. Обучить LayoutLMv3 на 5 k размеченных сканов (transfer‑learning).  
2. Сконфигурировать Tesseract + набор правила‑шаблонов.  
3. Оценить обе стратегии на hold‑out‑наборе (1 k сканов).  
4. Сравнить **F1** (ключевые поля) и **latency**.  
5. При равных метриках выбрать менее ресурсоёмкое решение (Tesseract).

#### Прогноз оттока клиентов  

| Кандидат | Почему в шортлист | Требуемые ресурсы | Приёмочные метрики |
|----------|-------------------|-------------------|--------------------|
| **LightGBM** | Хорошая интерпретируемость, быстрый inference | CPU 2 vCPU, 8 GB RAM | Recall ≥ 0.80, Precision ≥ 0.25, latency ≤ 30 ms |
| **CatBoost с таргет‑энкодингом** | Автоматическая работа с категориальными признаками | CPU 2 vCPU, 8 GB RAM | Same |
| **Deep FM** | Учёт взаимодействий признаков, более гибко при больших разреженных данных | GPU 1 × Tesla T4 | Recall ≥ 0.80, Precision ≥ 0.25, latency ≤ 30 ms (GPU) |

**Процедура выбора**  

1. Сформировать обучающий набор: 70 % исторических клиентов + 30 % контрольных слабых меток.  
2. Обучить все три модели, выполнить 5‑fold валидацию.  
3. На валидации измерить **Recall**, **Precision**, **ROC‑AUC**, **latency**.  
4. Провести **ROI‑анализ**: подсчитать ожидаемую прибыль от удержания при разных порогах вероятности.  
5. Выбрать модель, максимально увеличивающую **ROI** при выполнении бизнес‑порогов (Recall ≥ 0.80, Precision ≥ 0.25) и удовлетворяющей требованиям интерпретируемости.
