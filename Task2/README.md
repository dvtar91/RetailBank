# Задание 2. Оценка готовности данных, размещения и выбор модели

**Цель задания:** определить, готовы ли данные и где размещать решение, прежде чем проектировать сервис.

Для каждой из трёх инициатив оцените готовность данных: источник правильного ответа, качество, объём по важному классу, разметка, смещение отбора, репрезентативность, право использовать, владелец. Вердикт — один из четырёх: готово / можно начинать пилот / разрыв с планом закрытия / заблокировано.

Выберите размещение, по модели сформируйте предварительный шортлист и процедуру окончательного выбора:

* Размещение — из карты вариантов (публичный API, выделенный контур провайдера, self-hosting в облаке, on-prem, гибрид по звеньям), сначала отсекая недопустимое по жёстким ограничениям, потом сравнивая оставшееся.
* Отдельно разведите решение для пилота и для целевого продакшена — они не обязаны совпадать.
* Шортлист собирайте под свой выходной контракт и свои сценарии, а не по публичному рейтингу. Подготовьте процедуры проверки шортлиста:
  - какие кандидаты остаются после отсечения по жёстким ограничениям и почему;
  - из каких сценариев вы соберёте приёмочный набор и сколько примеров нужно;
  - какие метрики и пороги считаете приёмочными и откуда взялись их значения;
  - что означает провал на конкретном сценарии;
  - при каком результате решение меняется. Фраза «модель X даёт 92 % точности» без источника — минус, а не плюс.

У флагманской инициативы есть отметки «эскалировано» моделью, но подтвержденных случаев мошенничества — единицы. Для обучения с учителем этого недостаточно. Назовите, каким путём вы получаете источник сигнала и что этот выбор означает для сроков и стоимости:

* вероятностная контрольная выборка операций, размеченная экспертами, — способ получить несмещённую оценку того, что происходит в непроверяемой части потока;
* разметка силами финмониторинга по гайдлайну с оценкой согласованности между разметчиками;
* слабые метки — срабатывания правил, внешние сигналы, отметка об эскалации и исход расследования — с честной оговоркой, что эскалация не равна подтверждённой схеме и обучение на ней воспроизводит логику существующих правил;
* постановка без учителя: ранжирование операций на ручную проверку вместо вердикта «схема / не схема».

Любой из этих четырёх путей допустим, если вы явно называете его цену и риск, включая путь через слабые метки, при условии честной оговорки, о которой сказано выше.

Если выбранный путь на практике означает «размеченных данных пока недостаточно для обучения с учителем, сначала нужна программа их сбора», то задания 3–4 выполняются не для классификатора, а для сервиса приоритизации ручной проверки: он не выносит вердикт «схема / не схема», а меняет порядок очереди.

Разметка при этом накапливается из двух источников сразу — из разобранной приоритетной очереди и постоянной вероятностной контрольной выборки, случайной или стратифицированной по сегментам и суммам. Только очередь брать нельзя: если размечать исключительно то, что извлекла модель, вы получите новое смещение отбора — теперь уже собственного производства.

### Артефакты: 

* Для флагмана составлен ADR — контекст, жёсткие ограничения, рассмотренные варианты, решение по данным, размещению и модели, допущения, риски, план выхода от вендора, триггеры пересмотра.
* Заполнены разделы 2–5 паспорта инициативы (постановка, качество, данные, эксперимент) по трём инициативам.

### Сильное решение: 

* Дефицит данных назван точно — какого именно ресурса не хватает и чем это отличается от других дефицитов.
* Учтено, как формировалась историческая выборка проверок и что это значит для выводов по непроверенной части.
* Поток чувствительных данных разобран по границам контура, а вопросы допустимости адресованы комплаенсу и юристам, а не решены самостоятельно из общих соображений.
* Решения для пилота и для целевого продакшена разведены.
* В ADR есть допущения и триггеры пересмотра.

Загрузите ADR и разделы 2-5 паспорта инициативы в директорию Task2 вашего репозитория.
